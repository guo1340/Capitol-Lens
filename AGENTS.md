# Frontend requirements

- Keep economic and technical explanations in one central dictionary.
- Place a small question-mark button beside unfamiliar terms. Dictionary
  explanations appear in a tooltip on hover or keyboard focus, with tap/click
  support for touch devices and Escape to dismiss. Do not scatter separate
  definitions in page prose or use unexplained jargon in controls.
- Support both light and dark mode, including charts, tooltips and dialogs.
- Use plain language suitable for a beginner. Distinguish transaction dates,
  public filing dates, simulated execution dates and quote timestamps.
- Never label historical/cached prices as live or current. Show provenance and
  stale/unavailable states. Never fabricate successful API responses or returns.
- Preserve the Python research code and its reproducible historical results.
- Stage 1 is research and visualization only; no brokerage connection or orders.
